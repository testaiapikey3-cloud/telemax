# TeleMAX — исправление очереди сообщений

## Что исправлено
- WebSocket-клиент больше не отбрасывает сообщение молча, если соединение временно отсутствует.
- Непереданные сообщения помещаются во временную очередь в памяти и отправляются после восстановления соединения.
- После регистрации аккаунта клиент сначала отправляет пакет `register`, затем очищает очередь, чтобы сообщения не опережали регистрацию.
- Очередь ограничена 500 сообщениями на экземпляр приложения.
- Удалён `local.properties` с локальным путём Android SDK; его создаст Android Studio.

## Важно для реальной переписки между устройствами
Приложению нужен доступный сервер TeleMAX. По умолчанию `TELEMAX_SERVER_URL` — заглушка `ws://YOUR_PUBLIC_SERVER_IP:8080`. Задайте адрес своего сервера в `gradle.properties`, например:

```properties
telemaxServerUrl=wss://chat.example.com
telemaxAdminKey=REPLACE_WITH_LONG_RANDOM_SECRET
```

Для локальной проверки на одном компьютере сервер запускается командами из `server/`:

```bash
npm install
npm start
```

Для Android-эмулятора адрес хоста обычно `ws://10.0.2.2:8080`; на физическом телефоне укажите LAN IP компьютера для локального теста либо публичный домен с TLS (`wss://`). Не используйте тестовый admin key в открытом сервере.

## Ограничения проверки
Исходники сервера проверяются `node --check`. Полная сборка APK требует Android SDK и Gradle; этот архив содержит исходный проект, а не готовый APK. Очередь на Android хранится в памяти и теряется при принудительном завершении приложения. Серверная офлайн-очередь хранится в `server/server-state.json`.
